# ADR 0006: JSON出力を外部ライブラリを使わず自前実装する

## Context

Phase 4 で `--format json` を追加するにあたり、出力スキーマ (モデル/入力パス・閾値・画像サイズ・検出結果の配列、動画では`frame`/`fps`も付く) は固定かつ小さい。`nlohmann/json` のような成熟したライブラリを使えばDOM構築+シリアライズが数行で書ける一方、ADR 0003 で確立した「発見(`find_package`)と取得の分離、依存は最小限」という方針に新たな依存を1つ足すことになる。MSYS2 (`mingw-w64-ucrt-x86_64-nlohmann-json`) と Ubuntu apt (`nlohmann-json3-dev`) の両方にパッケージ導入手順を追加する必要があり、CI (`ci.yml`) にも `apt-get install` の1行が増える。

出力側専用 (パースは不要) であり、キー集合が固定なので、ストリーム出力の逐次書き込みで十分に賄える。ADR 0004 (NMS自前実装) と同様、「小規模で仕様が閉じているものは自前実装を優先する」という判断軸をここでも適用する。

## Decision

`src/io/result_writer.cpp` に、`std::ostream` への直接書き込みでJSONオブジェクトを組み立てる小さなシリアライザ (`WriteJson`、内部で `JsonEscape` を使う) を実装する。DOM構築は行わず、キーと値を決め打ちの順序でそのまま出力する。文字列値 (ラベル名・パス) は `"` `\` `\n` `\r` `\t` と `0x00-0x1F` の制御文字をエスケープする。数値は `std::ostream` の既定精度で出力し、テキスト出力 (`WriteText`) と数値表現を揃える。

動画は1フレーム1行のJSON Lines形式にする (全フレームをメモリに溜めずパイプで逐次処理できるようにするため)。

## Consequences

- 新規の外部依存が増えない。MSYS2/apt双方のパッケージ導入手順・CI設定に変更が要らない
- スキーマが増える (ネストしたオブジェクト、配列の配列など) 場合はエスケープ漏れ・カンマ位置ミスのリスクが上がる。現状の平坦なスキーマの範囲では `tests/test_result_writer.cpp` で個々のフィールド・エスケープ・境界値 (検出0件、範囲外class_id) を回帰テストしている
- 将来、入力側 (設定ファイル読込等) でJSONパースが必要になった場合はこの判断を見直し、パーサも必要とするならライブラリ導入を検討する

# ADR 0006: JSON出力を外部ライブラリを使わず自前実装する

## Status

Accepted

## Context

`--format json` の出力スキーマは固定かつ小さい (モデル/入力パス・閾値・画像サイズ・検出結果の配列。動画では `frame` / `fps` が加わる)。出力専用でパースは不要。

- **`nlohmann/json`**: DOM 構築とシリアライズが数行で書けるが、新しい依存が増える (ADR [0003](0003-dependency-resolution.md))。MSYS2 と apt の両方の導入手順と CI 設定に変更が要るため不採用

小さく仕様が閉じたものは自前実装を優先する、という ADR [0004](0004-hand-rolled-nms.md) と同じ判断軸を適用する。

## Decision

`src/io/result_writer.cpp` の `WriteJson` で、`std::ostream` に直接書き込んで JSON を組み立てる。**DOM は作らず、キーを決め打ちの順序で出力する。**

- 文字列値 (ラベル名・パス) は `"` `\` `\n` `\r` `\t` と `0x00-0x1F` の制御文字をエスケープする (`JsonEscape`)
- 数値は `std::ostream` の既定精度で出力し、テキスト出力 (`WriteText`) と数値表現を揃える
- **動画は 1 フレーム 1 行の JSON Lines にする。** 全フレームをメモリに溜めず、パイプで逐次処理できるようにするため

## Consequences

- 外部依存が増えず、導入手順や CI 設定を変えずに済む
- ⚠️ ネストしたオブジェクトや配列の配列などスキーマが複雑になると、エスケープ漏れやカンマ位置ミスのリスクが上がる。現状の平坦なスキーマは `tests/test_result_writer.cpp` で各フィールド・エスケープ・境界値 (検出 0 件、範囲外 class_id) を回帰テストしている
- 入力側 (設定ファイル読込など) で JSON パースが必要になったら、ライブラリ導入を再検討する
